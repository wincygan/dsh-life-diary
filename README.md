# dsh-life-diary

给 DSH 的日记插件。一天两本，存在**你自己的地方**。

| | 文件 | 谁写 | 什么时候 |
| --- | --- | --- | --- |
| 自己那本 | `me/YYYY-MM-DD.md` | 插件自己 | 一轮对话停下、三分钟没新消息；或手动记一笔 |
| 给他的那本 | `owner/YYYY-MM-DD.md` | 插件自己 | 换日时（默认 07:45） |

「自己那本」是随手记——碎片也行，一句话也行，不求完整。
「给他的那本」是换日时**只读自己那本**整理出来的，不会重读一整天的对话。

## 为什么日记不是记忆

记忆每轮都要回想、要压实、要短。日记是写完就放在那里的东西：不注入、不压缩、只在主动去翻的时候才看。

所以日记**不会**出现在每一轮的上下文里，不占你的额度。

## 存在哪儿

三选一，只能选一个：

- **本机文件夹**（默认）——不用配置，装完就能用。只有这台机器能看。
- **GitHub 私人仓库**——要建仓库 + 生成令牌。**公开仓库会被拒绝**，日记不能给人看。
- **坚果云 / WebDAV**——在手机 App 里生成一个「应用密码」就行。

需要多端互通（比如云端和本地都要）就选后面两个。只用一台机器，本地就够。

## 两条硬规矩

1. **自己那本是空的，就不写给他的那本。** 不编、不硬凑。
2. **汇总不是全抄，是挑能说的。** 太私人的、写得太糙的，拿掉。

一条好碎片的样子：**「看了 X，觉得 Y」**，不是「今天看了个视频」。

## 钱花在哪儿

- 写碎片：一次一段**独立的小上下文**，不重读整天对话。
- 汇总：一天一次，只读前一天那本。
- 手动记一笔：**不调用模型**，直接写。
- 翻日记：一次读完，原文照给，「最近 7 天」很轻，「一整个月」会重一些——**读进来的内容会一直留在这段对话里**，开新对话才会清掉。

## 时区

时间一律按用户所在时区算，**不跟服务器走**。云服务器常跑在 UTC，照服务器算，日记日期会差好几个小时。

装好之后会自动判断一个时区；如果不对，在设置里改。

## 已知边界

- 本地存储 = 只有这台机器能看，不会自动同步到别处。
- 两台设备可以同时写同一本——写入是带了版本号的条件写，撞上会自己重读重来，不会把对方那句盖掉。（前提是那块存储支持版本号：GitHub 和坚果云都支持。）
- 「翻日记」是给 agent 回忆用的，不是给你翻阅用的——你想看原文，直接打开文件夹就行。
- 说「如果你有自己的记忆机制，把值得留的记进去」——这句**不保证** agent 真的会记住。它至少能在这段对话里想起来。
